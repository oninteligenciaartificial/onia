## Encaje propuesto para ONIA

- Conservar la separación por funciones como forma de organizar trabajo. Sergio conserva las decisiones de negocio; el diagrama del autor no cambia nuestra autoridad ni permisos.
- Mantener el procedimiento propio de desarrollo. Superpowers y gstack no se incorporan juntos como instrucciones generales. La evaluación previa sigue en auditoria-30-repos.md; este post no aporta pruebas que la reemplacen.
- Mantener HyperFrames como motor elegido. FFmpeg es un apoyo de procesamiento; Higgsfield puede aportar recursos cuando el encargo y el acceso lo permitan. Remotion queda pospuesto para evitar dos motores de composición antes de necesitarlos.
- Mantener n8n para automatizar, según la decisión expresa de Sergio. La aparición de Zapier no justifica migrar ni sumar otro servicio.
- Investigar, escribir y programar publicaciones son funciones distintas. El catálogo no sustituye el trabajo pendiente de oferta, funnel, webinar, seguimiento y medición de ventas. Tampoco constituye una configuración de campañas Meta.
- Notion, Drive, Gmail y Calendar pueden servir para tareas delimitadas, sin convertirlos todos en memorias duplicadas. La fuente de reglas continúa siendo nuestra base vigente.
- Posponer nuevas suscripciones y servicios redundantes hasta identificar una tarea que las herramientas disponibles no resuelvan. La lista no acredita costos, cuotas ni acceso API incluido.
- Claude HUD y Claude in Chrome son candidatos ligados al entorno presentado; no asumir su funcionamiento directo en Codex. No comprar Claude sólo para reproducir la imagen.
