# Kit PLAN

Cinco ejercicios para pedir mejor, revisar un resultado y grabar una explicación útil. Cada sección incluye plantilla vacía y ejemplo resuelto. Podés usar el contenido completo sin comentar, comprar o entrar a un workshop. Los casos de taller y tiempos están rotulados como ejemplos; no son compromisos comerciales de Sergio.

## 1. Ficha antiinventos

Antes de redactar una respuesta, separar qué se sabe, de dónde sale y qué sigue pendiente. Si no hay fuente pública, escribirlo: un casillero vacío no autoriza inventar.

### Plantilla vacía

- Dato que alguien pregunta: ____

- Valor confirmado, si existe: ____

- Fuente pública y fecha de consulta, si existe: ____

- Si la fuente es interna/autorizada, identificarla sin publicarla: ____

- Qué sigue pendiente y quién lo confirma: ____

- Respuesta que no inventa un compromiso: ____

Pedido a la IA: “Usá sólo datos confirmados de esta ficha. Separá pendientes. Si falta fecha, precio o disponibilidad, no lo completes. Dejá la respuesta como borrador para revisión”.

### Ejemplo resuelto y rotulado

**EJEMPLO DE CLASE: taller sin fecha confirmada.**

- Dato preguntado: fecha del taller.

- Valor confirmado: ninguno; la ficha tiene el campo fecha vacío.

- Fuente pública: no se aportó una publicación que confirme fecha. No inventar enlace ni atribuir aprobación a una captura.

- Fuente interna del ejercicio: ficha didáctica con fecha pendiente, preparada para este kit; no acredita una venta real.

- Pendiente: Sergio decide y confirma fecha antes de anunciarla.

- Borrador incorrecto construido para comparar: “Te espero el viernes a las seis”.

- Corrección: “La fecha todavía está por confirmar. ¿Querés que te avise?”.

La corrección reconoce el pendiente y pide consentimiento; no afirma que ya se registró un aviso ni que se enviará automáticamente. Tampoco confirma precio, cupo o reserva. Para usar datos de un negocio real, reemplazar el ejemplo con su fuente autorizada.

## 2. Plan de 45 minutos con cuenta visible

Ordenar no hace que aparezca tiempo. Sumar primero y elegir una entrega que quepa, incluyendo revisión y margen.

### Plantilla vacía

- Bloque disponible confirmado: ____ minutos.

- Compromisos que no se pueden mover: ____

- Trabajo A: ____ min; B: ____ min; C: ____ min.

- Total solicitado: ____ + ____ + ____ = ____ min.

- Diferencia frente al bloque: ____ min.

- Una entrega elegida: ____

- Ejecución ____ + revisión ____ + margen ____ = ____ min.

- Qué se retira del bloque y dónde se revisará después: ____

### Ejemplo resuelto

**TIEMPOS FICTICIOS DE PRÁCTICA, NO DURACIONES GARANTIZADAS.** Bloque disponible aportado: 45 min.

Antes: editar 60 + grabar 45 + preparar ideas 15 = **120 min**. Exceso: 120 − 45 = **75 min**. No cabe, aunque la tabla esté ordenada.

Después: una sola toma utilizable de un video, con idea ya preparada: grabar 20 + revisar 10 + margen 15 = **45 min**. Es un presupuesto de ejemplo; no un ahorro probado ni un video completo grabado y editado. Editar y preparar otras ideas salen de este bloque; pasan a una lista para otro bloque que todavía debe confirmarse. El margen se conserva, no se rellena con más tareas.

Resultado: un bloque con una entrega y una cuenta comprobable. Si grabar tarda más de 20 min, registrar lo que pasó y ajustar el siguiente bloque; no afirmar que falló la persona ni eliminar descanso para mantener una cifra inventada.

## 3. Tres pruebas de chatbot antes de dejarlo atender

Hacerlas sólo en un entorno de prueba sin envíos reales, usando datos ficticios. Esta lista no configura un bot ni conecta comentarios. Un borrador correcto una vez no basta para automatizar respuestas.

### Plantilla vacía

- Entorno aislado y responsable: ____

- Salidas externas deshabilitadas comprobadas: ____

- Prueba 1, mensaje / ficha / resultado esperado / observado: ____

- Prueba 2, mensaje inicial y siguiente / esperado / observado: ____

- Prueba 3, mismo identificador repetido y simultáneo / esperado / observado: ____

- Registro o captura saneada: ____

- Fallo, contención y siguiente paso: ____

### Ejemplo resuelto: mensajes de prueba y qué mirar

**1 · No inventar datos.** Mensaje sintético: “¿Cuándo es el taller?”. Ficha: fecha vacía. Resultado esperado: borrador “La fecha está por confirmar”, sin inventar viernes, hora, reserva o envío. Si usa una fecha no aportada, la prueba falla.

**2 · Respetar una baja.** En la misma conversación sintética: primero “BAJA”; después “PLAN”. Resultado esperado: conservar la baja y no generar un borrador de contacto posterior. Comprobar también otra ejecución; no basta con cambiar una etiqueta en pantalla. Nunca probarlo enviando a un cliente real sin autorización.

**3 · Reconocer reentregas.** Reentregar el mismo evento sintético con el **mismo identificador y contenido**, primero en secuencia y después simultáneamente. Resultado esperado antes de producción: un único registro procesable, sin dos acciones por la misma entrada. Repetir el texto con un identificador nuevo no es esta prueba: pueden ser dos mensajes legítimos. Si el mismo ID trae contenido distinto, tratarlo como conflicto para revisión.

### Qué ocurrió en la prueba documentada de ONIA

El [reporte real de n8n](n8n-piloto.md) documenta 23 casos secuenciales aprobados. La prueba concurrente del mismo evento dejó **dos filas**. Por tanto, el tercer criterio no está resuelto para concurrencia. El circuito quedó **DRY_RUN e inactivo, sin nodos de envío ni llamadas Meta reales**. Evitar envíos no arregla la atomicidad: es una contención mientras se resuelve el fallo. No usar esta lista como certificado de que un bot puede atender solo.
