## Preflight y continuidad real

Comprobar en la instancia Cloud existente: entorno/readiness observado, checkout/HEAD y cambios, archivos reales y sus versiones. Leer las reglas pertinentes de esa instancia; el mensaje o estado idle de un chat no prueba acceso. Registrar herramientas no disponibles como tales. No usar resultados locales para acreditar estado de la VM.

Si un documento necesario falta o está desactualizado, transferir sólo un paquete textual saneado por la ruta existente, con manifiesto y hashes; nunca ONIA-CENTRAL, contexto personal, secretos o gigabytes de medios. El QA actual puede no estar publicado: su lectura y versión recibida deben quedar comprobadas, sin sobrescribir las reglas del checkout.

La evidencia de disponibilidad se incorpora en `recibos/`; antes de esa observación, Cloud se considera pendiente de comprobar. Las fuentes locales existentes no se anuncian como fuentes Cloud comprobadas.
